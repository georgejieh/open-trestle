# Changelog

All notable changes to released versions of Open Trestle will be documented in this file.

## Unreleased

### Added

- Added `trestle --help`, `trestle -h` and `trestle help`. Each prints the usage to standard output and exits 0, with the commands grouped as Everyday, Setup and keys, Integrations, Operators and Evaluation. A bare `trestle` without a terminal and an unknown command still print the usage to standard error and exit 2. The usage now opens with a pointer to the guides.
- Added reference pages under `docs/`: an index grouped by task, every command and flag, exit codes per command, every `failure_detail` value, environment variables and file locations, platforms, install, troubleshooting and privacy. See [docs/README.md](docs/README.md).
- Added `trestle update` for the packaged Linux amd64 install. It finds a newer build, shows it, asks for confirmation (or takes `--yes`), runs that build's own `verify-archive`, then runs `sudo -- <copy> upgrade` on the terminal and reports the new version and source revision. `--check` only reports, with exit `10` when an update is available, `0` when none is and `1` on an error. `--from FILE` installs a named archive. GitHub releases of `georgejieh/open-trestle` are read with one unauthenticated GET. A release qualifies only when the archive's Ed25519 signature verifies with a key pinned in `internal/update/release_keys.txt`. The signature covers the archive's version, target, tag, SHA-256 and size. No key is pinned yet, so the release channel refuses with "this build cannot verify releases; install the packaged release". A development install also reads `~/.local/share/open-trestle/updates/`, a private `0700` folder, and labels its build as an unsigned local build. The checks run in Go on a copy in a fresh private folder before any code from the candidate runs, and the copy is rechecked just before it runs. After at most one release list GET a day, the home screen and `trestle review` (on a terminal) show "Update available: X (you have Y). Run trestle update." The answer is cached in the state folder, and `OPEN_TRESTLE_UPDATE_CHECK=off` turns the check off. On a packaged install the home screen also adds an "Update Open Trestle" action. Added `tools/signrelease`, an offline Go tool that signs a release archive, prints its public key line and verifies it. No release workflow or key is added. See [updates](docs/updates.md).
- Added commit messages as stated intent to `trestle review` and `trestle local-git model-review`. The direct review reads the commits of `base..head` (reachable from head and not from base, newest commit time first, at most 1,024 commit objects and 4 KiB of each message). The context-assembly handler (identity version 8, `WithChangeIntent`) carries them as the generation context's `stated_intent` object, oldest first, labelled `author_stated_unverified`. The object holds at most 16 commits, 2 KiB each and 16 KiB in all. Text is cut on a character boundary and marked `truncated` with the full size, commits past a bound are counted in `commits_omitted`, non-text messages are kept without text, and `range_incomplete` is set when the walk stopped at its bound or at a missing parent. The text counts toward the 128 KiB source budget. Each message carries `risk_flags` and is secret-scanned before remote egress as a new `stated_intent_text` field role (sanitized egress receipt v1, in place). It does not enter the system channel or change the run plan, policy, routing or source selection. The verifier receives the same object. The walkthrough adds a stated intent line: `walkthrough.stated_intent` in JSON, with at most 8 subjects, control and format characters replaced and each subject cut at 120 characters. Text quotes the subjects, and Markdown adds a `### Stated intent` section with code spans. A run whose context carried commits declares change intent in its change features, so the `drift_auditor` intent condition now fires under `--specialists auto`. The daemon reads no commit messages, pull-request text or linked issues yet. See [commit messages as stated intent](docs/local-model-review.md#commit-messages-as-stated-intent).
- Added pattern hygiene (`internal/patternhygiene`). Every generation context except an investigation context records a `pattern_hygiene` object, computed from the acquired snapshots with no model. It reports three kinds of problem. First, 13 curated anti-patterns for Go, JavaScript and TypeScript, and Python are counted in the base and head of each changed file's directory, and reported when the head count is higher (spreading when the base already had it). Second, lint and type suppressions, workaround-justifying comments and TODO markers without an issue reference are reported on added lines. Third, absolute `NEVER`, `ALWAYS` and `MUST NOT` rules added to agent instruction and skill files are reported. A suppression on or beside a workaround comment is a `root_cause_not_fixed` note of severity low. Matching is lexical, over a line lexer that keeps string literals and comments apart. At most 32 directories, 128 files a side and 8 MiB of base text are compared, and a directory past a bound is not compared at all. The object holds complete counts and at most 16 items placed on changed sources by `source_id` and line, with no repository text. The walkthrough reports it in `verified.pattern_hygiene` (each item `origin` `deterministic`), and text and Markdown show a `pattern hygiene:` line. It does not change status, CI disposition or exit code. See [pattern hygiene](docs/local-model-review.md#pattern-hygiene).
- Added the repository index and `trestle index build|status|query`. It records every file of a commit with its role and status and the syntax analysis of each source, test and generated file, analysed once per blob in worker processes and kept in the setup folder, and answers definitions, reference candidates, tests, imports and the dependents of a change as JSON. See [repository index](docs/repository-index.md).
- Added per-file syntax analysis for Java, JavaScript, TypeScript, TSX, Python, C, C++, C#, Rust, Swift, PHP, Ruby and HTML (`internal/syntaxwasm`), next to the `go/parser` analyzer for Go, in the language-neutral `syntaxanalysis` model. Tree-sitter grammars compiled to WebAssembly run under wazero with a query pack per language, and each file gets its definitions, references, imports and enclosing definitions, with parse errors, limits and failures as coverage gaps. A C++ header named `.h` is analysed as C++, and the inline scripts of an HTML page are analysed as JavaScript or TypeScript. The modules are built reproducibly by `tools/build_syntax_modules.py`. See [syntax analysis](docs/syntax-analysis.md).
- Added nuance traps to the `bug_hunter` and `frontend` skills, both now profile version 2. They cover Go goroutine and channel leaks, `defer` in a loop, loop-variable capture before Go 1.22, `time.Sleep` and library `panic`, Python mutable defaults and bare `except:`, and React `useEffect` and imperative timers, with a pointer to lines `pattern_hygiene` cites.
- Added ranking, deduplication and a pre-existing class to `trestle local-git model-review` and `trestle review`, decided after verification with no model call. One shared rule (`localreview.DeduplicateFindings`) merges verified findings within a run, across specialist set members and across repeated runs. Two findings merge when they share path and side, the range overlaps the representative's, the categories are the same or of one family (security is its own), and the normalized title and claim are near-identical (four fifths of the distinctive words shared, no differing identifier or number). A second, location-anchored pass merges paraphrases of one defect at one place. It requires the same path and side, overlapping ranges, categories of one family that is not security, either the same changed declaration of the semantic-impact profile or, when no changed declaration holds them, one range of at most five lines, and statements that share at least half of their words (see Fixed). Security findings and uncategorized findings merge only by the first rule. The strongest verified finding represents the group at its own location, and the other wordings are kept: text and Markdown show `also reported as:`, and set JSON has `merged[]` with each member, title, claim and `rule` (`near_identical`, `same_declaration` or `same_lines`). A direct result records `declaration_anchors`, the changed declaration that holds each anchored finding. The import checks them against the findings and uses them to re-derive `rank`. `localreview.RankFindings` orders by severity, then by the number of origins that confirmed the defect and their independence, then by distinct evidence and a narrower range. A finding is pre-existing when it lies only on unchanged head lines (outside changed lines and 8-line deletion windows), cites no changed-hunk or removed-lines evidence, and the change provably cannot reach it (see Fixed). Only direct runs classify. A completed direct run's result (schema version 6, in place) adds `rank` and `pre_existing`. A result whose every finding is pre-existing keeps status `findings` with `ci_disposition` `inconclusive` (exit 3 by default, 0 under `findings` and `always-zero`, 3 under `strict`), and a review set follows the same rule. `localreview.ParseCompletedResult` re-derives `rank`, treats an imported `pre_existing` list as advisory and requires the readiness disposition. See [ranked findings and the walkthrough](docs/local-model-review.md#ranked-findings-and-the-walkthrough).
- Added a walkthrough to direct review results (`walkthrough`, schema version 6, in place) and review sets. It shows secret-scan receipt totals, which local-only requests also have, the static checks, style detection, the semantic-impact profile and the verifier's confirmed, rejected and inconclusive counts. It adds a per-file change summary (added, removed and changed Go declarations, line counts from a fresh bounded diff, exact-content renames). It also lists missing verification: changed functions and methods that no test file references, as an informational class that does not change status. When the walkthrough exceeds its output limit it is omitted with `walkthrough_omitted_output_limit` rather than truncated.
- Added `--format markdown` to `trestle local-git model-review` and `trestle review`. It writes a pull request summary comment with what was verified, the changes, missing verification, the confirmed findings in rank order (a set names the members that confirmed each) and the pre-existing findings. Model-written text is escaped and cannot open links, HTML, headings or mentions or become an autolink. Added `--all`, which lists every confirmed finding in text and Markdown. By default they list high, critical and medium findings and count the rest. When no confirmed finding is high, critical or medium, they list the lower-severity ones instead, at most ten in rank order, and count the rest (this also applies to the first review in `trestle init`). SARIF lists results in rank order with `trestleRank` and `trestlePreExisting`.
- Added `trestle review` without a fixture path. In a repository that `trestle init` set up, it reviews the latest change, `HEAD` against its merge base with the default branch, in one step. It finds the setup folder the way `trestle init` does (or `--directory PATH`), keeps the saved review command's route inventory, runtime policy, tenant, repository and source labels, egress and timeout, and replaces only the two commits. The base is one `git merge-base HEAD BRANCH origin/BRANCH`, so a local default branch that is behind or ahead of `origin` does not pull commits already on the other into the review. On the default branch itself only `origin`'s copy counts, so unpushed commits are the change. `--base REF` and `--head REF` pick commits, and `--format`, `--timeout`, `--profile`, `--specialists`, `--max-specialists` and `--exit-code-policy` pass through to `trestle local-git model-review`, whose result, egress, secret-scanning and spending messages and exit codes it keeps. It says when uncommitted or untracked changes are not included and that committing them includes them, and it writes nothing into the repository. It stops with exit 3 before sending anything when there is no setup, no committed change or no API key. `trestle review <path>` still reviews a fixture file. See [getting started](docs/getting-started.md#running-it-again).
- Added hidden API key entry to `trestle init`. When the chosen remote provider's key variable has no key in the environment or the credential store and standard input is an interactive terminal, the wizard asks for the key with the terminal's echo off (termios on Linux and macOS, the console mode on Windows). It restores echo before printing anything else, also on Ctrl-C or end of input, and does not read a key when echo cannot be turned off. It checks an OpenRouter key with one free `GET /api/v1/key` and asks again when OpenRouter refuses it (HTTP 401 or 403). Ollama Cloud and OpenCode Go keys are kept unchecked with a note. "Save this key for future reviews?" saves the key once the setup is saved, so a declined setup writes nothing. `n` keeps the key in memory for the session and prints `read -rs NAME && export NAME`. Without a terminal or with `--no-input`, nothing is asked. A re-run of `trestle init` asks the same way when the setup's key is missing. `spending.OpenRouterKeyStatusError` now carries the status of a refused key read. See [API keys](docs/keys.md).
- Added an owner-only credential store for provider API keys, `$XDG_CONFIG_HOME/open-trestle/credentials` (default `~/.config/open-trestle/credentials`). The folder is `0700`, and each variable name has one `0600` file holding the key. Files are written through `internal/fileauthority` with atomic replacement by rename, and are refused when the file is a symbolic link, has broader permissions or has another owner. Added `trestle keys` (`list`, `set VAR`, `remove VAR`). `list` shows each key variable, where its key comes from and at most its last four characters. `set` reads the key with hidden input or from a pipe, not as an argument, checks an OpenRouter key and saves nothing when it is refused (exit 4). See [API keys](docs/keys.md).
- Added a home screen: `trestle` with no arguments, with a terminal on standard input and output and neither `NO_COLOR` nor `TERM=dumb`. It shows a status card (repository, setup folder, models, provider and zero data retention, where the key comes from, this month's recorded spending, and the last review) and numbered next actions: review the latest change, see spending, change the API key, re-run setup, read the guides. In a repository without a setup it offers `trestle init`. It reads only local files. Anywhere else `trestle` prints the usage text and exits 2, as before.
- Added per-key spending limits and a local usage ledger for `trestle local-git model-review`, a new `trestle usage` command and an optional spending question in `trestle init`. A limit belongs to one API key, keyed by the provider ID and the credential reference identity that setup records for the key variable (`runtimeconfig.CredentialReferenceIdentity`), so every setup that names the variable shares it. A limit has an amount in whole cents, a calendar period in UTC (`week` from Monday, `month`, `year`) and alert percentages (default 80 and 100). Before each review run, and before any credential is read or request sent, a key whose recorded spend in the current period is at or over its limit refuses the run with the new `failure_detail` `spending_limit_reached` (failure `policy`, status `refused`, CI `blocked`, exit 4, `run_status` `not_opened`, result schema version 6 without `token_usage`) and a hint naming `trestle usage`. A run whose worst case (two requests at the per-request bound, or an investigation policy's budget) could pass a limit runs with a warning. After a run that sent at least one request, one entry is appended under a file lock. It records the time, review run ID, runtime policy identity, keys, models, requests sent, `usage_known` and the cost. The cost is the settled `actual_cost_micro_usd` (`cost: settled_usage`) or, when usage is unknown, every sent request at its settled cost or its reservation (`cost: reservation_upper_bound`), with `price_basis: route_max_price`. A crossed alert percentage prints one line such as "Spending alert: $8.12 of your $10.00 monthly limit for OPEN_TRESTLE_PROVIDER_OPENROUTER (81%)". Review set members are checked and recorded one by one, so a member refused at the limit stops the set. Spending lines go to standard error, and text output ends with each limited key's state. The figures are an upper-bound estimate at the highest pinned price, not a bill, and the limit is best effort. Routes on this machine and the Ollama sign-in route use no key and are not recorded, and a usage folder that cannot be read is reported and does not block a review. `trestle usage` shows every limited key and every key with spend this month. For an OpenRouter key whose variable is set, it adds OpenRouter's figures from one `GET https://openrouter.ai/api/v1/key`, reading only the numeric usage and limit fields and `limit_reset`. A failed read says "OpenRouter's usage could not be read". `trestle usage set --credential-env VAR --limit USD [--period week|month|year] [--alert 80,100] [--provider ID]` and `trestle usage clear --credential-env VAR` change limits. Records live in `$XDG_STATE_HOME/open-trestle/usage` (default `~/.local/state/open-trestle/usage`, mode `0700`, files `0600`) as JSON under two new schemas, `open-trestle/spending-limit` v1 and `open-trestle/usage-ledger-entry` v1, with one ledger file per UTC month. They hold no key, source, prompt or reply. `failure_detail` and result version 6 take the new value in place. The daemon does not record or enforce spending yet. See [spending limits](docs/spending-limits.md).

- Added `trestle init`, a guided first-setup wizard for the repository in the current directory. It proposes the merge base of the default branch and `HEAD` as the base and `HEAD` as the head, summarizes the change between them, explains the two-model review, and lets the operator choose OpenRouter, Ollama Cloud, OpenCode Go or a loopback model server. It reads public model lists and the local server's `/v1/models` through a new side-effect-free `modelcatalog.List`. It requires distinct finder and checker models, flags small models and refuses Ollama Cloud models on the local route (see Security). It asks only for a credential environment variable name, requires a typed `yes` for each existing bootstrap declaration, and then calls `setup bootstrap init` and `check` in-process. Check results render as plain pass, waiting, fix and optional lines with remedies. The printed review command runs only after explicit consent, and `NEXT-STEPS.txt` is saved beside the protected configuration. Re-running detects an existing setup and offers check or review without overwriting. Every answer has a flag. `--no-input` lists all missing answers and writes nothing, and there is no blanket declaration bypass. Plain line-based prompts work over SSH and with scripted input. Local mode prepares only the direct checkout review through the new `setup bootstrap init|check --scope direct-review`, so an ordinary packed clone with a `0755` objects folder works and the check runs storage, owner, policy and dry-run checks without daemon tokens. The daemon scope and its commands are unchanged. Before any provider question the wizard reads both selected commits with the review's reader and detects a development build without scanner digests, explaining the packaged-build commands while local mode stays available. For OpenRouter it fills in every model fact from OpenRouter's public API and recommends zero data retention (see Changed). For OpenCode Go it offers a credential-free HTTPS fetch of each public evidence page, to compute its SHA-256 locally for confirmation. Account evidence is not fetched, and every declaration still needs a typed `yes`. Long paths are shortened on screen only. See `docs/getting-started.md`.

- Added `--provider ollama-signin` to `trestle setup bootstrap init` and the option "Ollama on this machine, signed in to Ollama Cloud" to `trestle init`. They are for a local Ollama daemon that serves Ollama Cloud models through the operator's `ollama signin` account. The wizard lists only the daemon's cloud models and detects the `ollama` command. See `docs/remote-model-review.md#ollama-signed-in-to-ollama-cloud`.
- `trestle local-git model-review` now recommends a standard style for each changed language that has a style detector but no style declared by the review's base tree. The style is read from the root of the base, as for `--specialists auto`, and EditorConfig alone does not count. The recommendations are gofmt and Effective Go; PEP 8 with Ruff or Black; Prettier with ESLint for JavaScript, TypeScript, Vue and Svelte; Prettier for CSS, HTML, JSON, YAML and Markdown; Google C++ Style through clang-format; rustfmt; and RuboCop. The text is a fixed table, not model output. Languages without a detector (Java, Kotlin, C#, PHP, Scala, Swift, shell, SQL, TOML) get none. Vendored, generated and removed files and lock files (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock` and the like) are not counted, and `bun.lock` now classifies as a dependency manifest for routing. ### Fixed

- A review run no longer fails when the machine's wall clock steps backwards during the run, as after an NTP correction, a virtual machine resume or in WSL. The control plane refused any transition observed earlier than the last recorded event with "run transition sequence mismatch", which surfaced as a failed review with `run: unknown` or an invalid session. Such a transition is now recorded at the last event's time, so recorded event times still never decrease. Lease expiry, renewal and retry times are measured against those recorded times, so a step can neither expire nor extend a lease.
- A local deterministic `trestled` could refuse a review with `503` or stop. Admission saved the plan, opened the run and advanced it as separate journal writes, so a worker pass in between either found a plan with no opened run and stopped the daemon with `review run is not opened`, or held its scope marker while admission wrote and admission failed with `run scope effect is unresolved`. A plan left without an opened run, for example after a canceled admission, also stopped the daemon, again after each restart. - Aligned the PostgreSQL run journal with the memory and file journals on owner context-input and prepared-packet guards.
- Provider response-body read failures are now classified as timeout, cancelled, or transport failures rather than invalid responses, and invalid UTF-8 in OpenRouter and Responses output is rejected.

### Security

- The GitHub Actions example (`examples/github-actions/open-trestle-review.yml`) put SARIF `message.text` and fix guidance, which are model output, and repository paths into the job summary unescaped, and reviewdog posted the same text as pull-request comments. The workflow now writes a jq module that escapes that text with the rules of `localreview.MarkdownText` and `MarkdownCode` (the `--format markdown` renderer), including autolink defusal. The job summary is rendered through the module, and reviewdog reads a copy of the SARIF whose message text is escaped and whose `message.markdown` is removed. The SARIF uploaded to code scanning keeps the raw text. A repository test runs the module with jq, offline, and checks it byte for byte against the Go renderer. The workflow itself is untested on GitHub.
- The daemon's GitHub publisher no longer lets model-written titles and claims become links. Its Markdown escaping now also defuses autolinks (a zero-width space before a scheme's colon such as `https:` or `mailto:`, inside `www.` and on both sides of `@`), as the new Markdown renderer does.
- A saved provider key is a plaintext file protected only by file permissions, like other command-line credential files. It is kept from other accounts on the machine, not from programs running as the same account, the administrator or backups. The environment always wins, so a key can stay in an external secret manager. On Windows the store's ownership checks are unavailable, so saving is refused and a typed key is used for the session only. A test sends a canary key through a full review in each output format and finds it only in the `Authorization` header. See [API keys](docs/keys.md#threat-model).
- Updated the Go build toolchain to 1.26.11 in the root module, the isolated secret-scanner worker, and the isolated govulncheck module, for GO-2026-6859 (an HTTP/1 server crash from a `MaxBytesReader` header race in `net/http`, fixed only in Go 1.26.11), and golang.org/x/text to v0.41.0 with the required x/sync v0.22.0 dependency. The product Go minimum remains 1.25.0. Updated two secret-scanner worker dependencies that the passive vulnerability gate found reachable: `github.com/andybalholm/brotli` from v1.2.1 to v1.2.7 (GO-2026-6888, excessive memory allocation decompressing crafted streams) and `github.com/klauspost/compress` from v1.18.6 to v1.20.2 (GO-2026-6865, panic on two-block frames). Betterleaks stays v1.8.1, and Brotli's `flate` package is no longer linked, so its license file left the linked-license set. This is a new scanner profile, `public_detect_run_re2_purego_go1.26.11_linux_amd64_v1`. New scans write it, and the daemon accepts a live scan only under it, from a worker whose binary digests match the values injected at packaging. Secret-scan responses, sanitized egress receipts, and publication content scan receipts recorded under the go1.26.10 profile still read back, and their schemas and parsers accept exactly those two profiles. The worker binary vulnerability baseline was regenerated, and three GO-2026-5841 `github.com/klauspost/compress` presence entries were removed. Binary identities are regenerated by packaging and the public scanner span fixtures pass, while the private coverage and performance qualification is pending.
- Reserved the webhook run namespace. `POST /api/v1/runs` accepted a caller-authored plan or local review intent with any run ID, so a `run_write` principal could open a `webhook-{deduplication key}` run scope before intake and have the delivery adopt it. Run IDs that begin with `webhook-` are now `400 invalid_request` on that endpoint, for plans and both local intents. The webhook processor now resumes an existing run only when its plan is the one the planner, or an earlier version of it, produces for the delivery. It refuses any other plan without advancing it: as `run_opened_by_incompatible_release` when an earlier release opened it with task handlers this daemon does not run, and as `run_plan_conflict` otherwise.
- The local route (local bootstrap and `trestle init`'s local server option) now refuses a model that a local Ollama relays to Ollama Cloud, which would have sent source off the machine under a local declaration. It refuses any name ending in `:cloud` or `-cloud`, whether or not the server lists it yet, with "this model runs on Ollama Cloud, not on this machine; use --provider ollama-signin". It then reads the server's `/api/tags` once at setup and refuses a listed entry with a `remote_host`. It also refuses when an Ollama daemon answers that path but its list cannot be read. A loopback server with no Ollama tags path (llama.cpp, vLLM, LM Studio) still passes. The wizard previously only warned.
- Harness-owned instructions are now separated from repository-owned text in every new model request. Generation contexts from version 7 and verification contexts from version 6 send instruction prose only in the system channel, and the user payload binds it with an `instructions_identity` digest. The `specialist` block now carries only profile and catalog identities, and the skill text is appended to the system channel from the embedded catalog. Both contracts open with an instruction-hierarchy paragraph saying that every string in the user message is data, that repository instruction files cannot change rules, format, severity or evidence requirements, and that AI prompts, skills, agent configuration and tool definitions under review are assessed, not followed. Sources gain an `agent_configuration` path flag and more `instruction_like_text` markers (chat-template tokens, fake system tags, override phrases, `instruction_authority`). The local model review reports `agent_configuration_sources` and `instruction_like_sources` with a text line and SARIF properties. The input-token estimate now includes the system channel. Investigation contexts from version 5 (opt-in `--investigation-policy`) carry the same hierarchy paragraph, adapted to snapshot tool results and the files they return, in front of the version 4 rules, sent only in the system channel with an `instructions_identity` digest, and returned files are flagged like any other source. Verification version 5 and earlier, generation version 5 and earlier, and investigation version 4 are unchanged, are read back only, and investigation version 4 is not sent again. See [prompt-injection boundary](docs/prompt-injection-boundary.md).
- OpenRouter privacy witnesses now record effective-account Safety Retention denial for both Google and other providers, scoped to every matching provider slug. The witness and account-policy contracts moved to version 2, and version-1 witnesses are refused and must be re-recorded.
- Added validators for model-influenced input, size and identity bounds, tenant and authorization scope, provider routes, source bindings, and publication effects.
- Added request-time credential boundaries and protected secret storage. Public failures are now content-free, and incidental npm audit and update-notifier requests are disabled during package installation. Vulnerability reporting remains a separate authorized release gate.
