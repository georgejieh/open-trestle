# Changelog

All notable changes to released versions of Open Trestle will be documented in this file.

## Unreleased

### Added

- Added `GET /api/v1/tenants/{tenant}/repositories/{repository}/runs/{run}/refusal` (`run_read`), which returns the content-free refusal intake recorded for a webhook delivery instead of opening its run (`open-trestle/delivery-refusal-response` v1, new schema), `client.GetDeliveryRefusal`, and `trestle runs refusal`; `trestle runs status` names the refusal reason when no run exists. `trestle tui`, the web console, the MCP `open_trestle.run_status` tool, and the ACP review-state prompt report the recorded refusal and its fixed reason when a scope's delivery was refused and its run is not found; any other failure to read the run is still reported as such. `client.GetRun` returns a not-found answer as an error that is also `controlplane.ErrRunNotOpened`. See [daemon API](docs/daemon-api.md).
- A failed final review result (diagnostic set v7) now carries `context_refusal` when its context task recorded a route refusal: `route_context_insufficient` with the required, input, output and declared token counts, or `no_eligible_route`. The copy is bound into the set identity, and the web console shows it with the local review's hint.
- Added a closed, content-free failure reason for source acquisition tasks: `no_merge_base`, `nothing_to_review`, and `merge_base_unavailable`. A reason travels in task completion v3, the v7 `task_failed` event, and receipt v3 (`failure_reason` on the task), survives journal replay, and is admitted only for an `acquire_source` task of the bound plan. Earlier completion, event, and receipt versions are unchanged. See [protocol contracts](docs/protocol-contracts.md).
- Added `trestle init`, a guided first-setup wizard for the repository in the current directory. It proposes the default branch and `HEAD`, summarizes the change, explains the two-model review, and lets the operator choose OpenRouter ZDR, Ollama Cloud, OpenCode Go or a loopback model server. It reads public model lists and the local server's `/v1/models` through a new side-effect-free `modelcatalog.List`, requires distinct finder and checker models, flags small models, refuses Ollama Cloud models on the local route (see Security), asks only for a credential environment variable name, requires a typed `yes` for each existing bootstrap declaration, and then calls `setup bootstrap init` and `check` in-process. Check results render as plain pass, waiting, fix and optional lines with remedies; the printed review command runs only after explicit consent, and `NEXT-STEPS.txt` is saved beside the protected configuration. Re-running detects an existing setup and offers check or review without overwriting. Every answer has a flag; `--no-input` lists all missing answers and writes nothing, and there is no blanket declaration bypass. Plain line-based prompts work over SSH and with scripted input. Local mode prepares only the direct checkout review through the new `setup bootstrap init|check --scope direct-review`, so an ordinary packed clone with a `0755` objects folder works and the check runs storage, owner, policy and dry-run checks without daemon tokens; the daemon scope, its private loose-object source rules and its commands are unchanged. Before any provider question the wizard reads both selected commits with the review's reader and detects a development build without scanner digests, explaining the packaged-build commands while local mode stays available. For OpenRouter it can read the model list with an already-set key variable, proposes the documented ZDR guide for broker and slug evidence, reuses the finder's slug and evidence for the checker on Enter, and offers a bounded, credential-free HTTPS fetch of each public evidence page to compute its SHA-256 locally for confirmation; account evidence is never fetched and every declaration still needs a typed `yes`. Long paths are shortened on screen only. See `docs/getting-started.md`.

See `docs/remote-model-review.md`.

- Added `--format sarif` to `trestle local-git model-review`: SARIF 2.1.0 built from the verified findings with the existing SARIF types, `ruleId` `open-trestle/<category>`, level from verified severity, `message.text` of title and claim, snapshot-bound and content-based `partialFingerprints`, unverified fix guidance as a labeled `trestleFixGuidance` property (not a `fixes[]` entry, which SARIF requires to hold `artifactChanges`), run properties for limitations, coverage, omissions and `trestleComprehensiveClearance: false`, and sorted deterministic bytes. A refused, unreadable, canceled or failed run is still valid SARIF with zero results, `executionSuccessful: false` and an explanatory notification.
- Added opt-in `--exit-code-policy default|findings|strict|always-zero` to `trestle local-git model-review` for CI steps. `findings` exits 0 when the run completed and no verified high or critical finding exists; `strict` only when it completed with no candidates; `always-zero` whenever a result was written. The default mapping and every output are unchanged, and no policy claims comprehensive clearance.
- Added opt-in `--specialists auto|none|ID[,ID...]` and `--max-specialists N` (default 3, at most 6) to `trestle local-git model-review`. `auto` derives change features from the general review's own recorded change and semantic-impact artifacts, plans across the packaged profile catalog without a model call, and keeps activated direct-review profiles in priority order up to the limit; every dropped profile is recorded with its reason. The general review and each selected specialist then run sequentially as separate, independently verified runs on the runtime policy's one route pair (per-profile route assignment is not applied; the planner's synthesized assignments are informational). No further member starts after cancellation or a member run that did not succeed. Output is the new `open-trestle/local-git-model-review-set` schema version 1 with the selection trace, member summaries and verified findings de-duplicated when findings share a path, category and overlapping lines and also an identical normalized title or, across members, a shared evidence ID or substantial word overlap (highest severity and narrowest range kept, contributors listed); text and SARIF (`trestleContributors`) render the merged set and exit policies apply to it. `--specialists none` and runs without the flag keep the single-review path and output; the daemon does not dispatch profiles.
- A `model-review --checkout` run now explains an unresolvable base or head on stderr (naming `git fetch --no-tags --depth=N origin <sha>` or `actions/checkout` `fetch-depth: 0` for a shallow checkout) and hints at partial clones whose file contents are missing. It still never fetches.
- Added `--provider ollama-signin` to `trestle setup bootstrap init` and the option "Ollama on this machine, signed in to Ollama Cloud" to `trestle init`, for a local Ollama daemon that serves Ollama Cloud models through the operator's `ollama signin` account. Init refuses without `--declare-ollama-cloud-signin`, refuses identical models and any credential variable, and reads the daemon's `/api/tags` once to require both models with `remote_host` `https://ollama.com`; `check` repeats the read and reports `ollama_cloud_models_listed`. The wizard lists only the daemon's cloud models, detects the `ollama` command, and with consent sends one fixed "Reply with OK" message to check the sign-in, offering to run `ollama signin` (only on `y`) and re-check after a 401 or 403. See `docs/remote-model-review.md#ollama-signed-in-to-ollama-cloud`.
- `trestle local-git model-review` now recommends a standard style for each changed language that has a style detector but no style declared by the review's base tree (read from the root of the base, never the head, as for `--specialists auto`; EditorConfig alone does not count): gofmt and Effective Go; PEP 8 with Ruff or Black; Prettier with ESLint for JavaScript, TypeScript, Vue and Svelte; Prettier for CSS, HTML, JSON, YAML and Markdown; Google C++ Style through clang-format; rustfmt; RuboCop. The text is a fixed table, not model output. Text output adds a `style:` line per language; JSON uses result schema version 5, which keeps the version 4 fields and adds `style_recommendations`; when a base style configuration file could not be read, only the languages that file could govern are listed in `style_withheld` instead of recommended, and `style_configuration_unread` counts the unread files. The advice never blocks, is not a finding and never changes status, CI disposition, exit codes or clearance; SARIF carries it at run level only (the `trestleStyleAdvice` run property and `note` notifications, never a result), and an `--investigation-policy` result with advice is version 5 with its `investigation` object. ### Changed

- `trestle profiles list` now prints one readable line per profile by default (ID, when it calls a model, whether `local-git model-review --profile` and `--specialists` accept it, and purpose) instead of about 43 KB of catalog JSON. The previous output, byte for byte, is available with `--format json`; `--format text` selects the new default explicitly.
- `trestle local-git model-review --specialists auto` now detects declared style, so `style_conformance` activates when the repository declares a style that governs a changed language. The style configuration files (`go.mod`, `.editorconfig`, Prettier, ESLint, flake8, pycodestyle, Ruff, `setup.cfg`, `tox.ini`, `pyproject.toml`, yapf, clang-format, rustfmt and RuboCop files) are read from the root of the review's base tree, never from the head, so a head edit to a style configuration cannot choose the style that same change is reviewed against and is reviewed as code. Contents come from the base snapshot artifacts the run already recorded, with no new Git read; a file over 64 KiB or not valid UTF-8, beyond 256 files, or past the 1 MiB change-features document bound is skipped whole and never truncated, and the selection trace counts skipped files in `features.style_configuration_unread`. Nested configuration files are not read. `agentprofile.NewChangeFeatures` now enforces the 1 MiB document bound at construction (`ErrChangeFeaturesTooLarge`), and `agentprofile.FitConfigFiles` selects the configuration files that fit. The new `agentprofile.IsStyleConfigFile` reports which names detection reads.
- Raised the model-list HTTP body limit (`modelcatalog.MaxResponseBytes`) from 1 MiB to 4 MiB. OpenRouter's public list measured 829,400 bytes (79% of the old limit) on 2026-11-08, and over the limit `trestle init` falls back to typing model IDs. The limit admits a fetch only and is not part of any stored catalog, digest or identity; the 8 MiB protected-file limit for catalogs and proposals is unchanged.
- Expanded versioned artifact, diagnostic, readiness, local-Git, setup, and transport contracts with strict offline schema reference and documentation-inventory checks.
- Published JSON schemas for deterministic evidence result versions 5 and 6 (`schemas/artifact/deterministic-evidence-result-v5.schema.json` and `-v6.schema.json`), which the analysis codec already writes for deletion-only changes. They differ from version 4 only in the version constant and the `no_changed_head_lines` and `deleted_lines` gap reasons, and a conformance test validates encoded results against them.
- Advanced diagnostic publication to version 5 while preserving earlier versions, binding the exact source check, analysis, change, verification context, coverage, omissions, and review state.
- Added diagnostic version 6 for deterministic observations, with analysis-result and changed-range lineage, schema-aware ACP/TUI/CLI/web semantics, and no independent-verification claim.
- Made web and VS Code distributions reproducible and freshness-checked in CI, with package-local npm policy that separates locked dependency retrieval from automatic audit requests and update checks.
- Sealed packaged alpha verification to a stable output-owned candidate copy and a no-follow working-tree snapshot bounded by entry count and regular-file bytes, including ignored and assume-unchanged files and recorded symlink targets outside `.git`.
- Independently validate phase-bound browser receipts and screenshot files, including strict JSON value types, exact review identities, fatal-zero browser metrics, viewport and PNG image dimensions, PNG structure and CRCs, and on-disk byte digests.
- Added base-side findings: a finding about removed code may be located on the removed base lines of a `removed_lines` source, in generation and investigation turns, and only cited removed text can verify it. Findings, verdicts and evidence bindings record their side, and readback checks every recorded side against its source, so base lines never read back as head lines. Each deletion point's removed text records the head line beside it (`head_line`). An emptied file and a removed file are now reviewed from their removed base text, bound as line-aligned chunks of at most 64 lines and 8 KiB, up to 32 KiB per file, with the rest of the file an explicit `removed_lines_limit` gap; that text is bound after every changed file, from the evidence budget they leave, and charged only the bytes it binds, removed files are read from a separate 64 MiB bound past which a file is one whole-entry `removed_lines_limit` gap, and a removed file that is not text binds nothing; they keep their whole-entry omission, so the review is never full clearance, and a change that only removes files is reviewed from that text alone, in the direct and investigation modes. New versions are emitted only when a base side is present: verified diagnostic set v8, verification-batch v2, candidate-batch v3 and verified-finding-set v3 for uncategorized batches, model-generation-input v4 for direct inputs and v5 for investigation inputs; versions that exist only in this development candidate were extended in place. SARIF places a base-side finding at the head line beside its deletion point and reports one with no head line as a run notification; GitHub publishes it in the review summary only; the console, terminal, text output, review sets and language server label it as removed base lines. `repository_context_anchor_omitted` again counts only `repository_context` anchors. See `docs/local-model-review.md#base-side-findings`.
- Model reviews now cover non-Go text files. Changed hunks of valid UTF-8 text outside `.go` are admitted as `changed_hunk` sources within the existing size and packet budgets; the `semantic_unsupported_language` coverage gap stays recorded for each such path and no structural evidence is claimed. Binary or non-UTF-8 hunks, `vendor/` and `node_modules/` paths, lock files (`go.sum`, `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `*.lock`), and `*.min.js`, `*.min.css`, and `*.map` files are omitted with the new reasons `non_text_content` and `excluded_path`. A change containing only such files still abstains with `unsupported_language`.
- Model reviews now include the base tree's root `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, and `.trestle/review-instructions.md` as `repository_context` sources (8 KiB per file, 16 KiB in total, whole-line truncation recorded as `repository_instruction_truncated`). They are read from the base snapshot, never the pull-request-controlled head: a file is used only when the head holds byte-identical content, a head edit or deletion is recorded as `repository_instruction_changed` and the edit is reviewed as an ordinary changed hunk, and a file absent from the base (including every file against an empty base) is not used. They remain repository-controlled evidence data, never instructions or authority, are selected after changed hunks only when they fit the remaining budget, and never turn an all-omitted change into a reviewable one. `repository_instruction_*` omissions are reported separately (`instruction_context_omitted`) and never count as source omissions, so they do not make a review incomplete. The model is told how to treat them under review-context schema version 7 (below).
- Candidate generation now uses review-context schema version 8, verification version 7 and investigation version 6. Each adds one sentence telling the model that `removed_lines` sources are base lines that the change removed, and how to report an issue in the removed code on them. Investigation version 6 also gives every raw tool result in `investigation.tool_results` a host-computed `risk_flags` array from the source rules, so returned file text carries the same attention markers as the sources it becomes; the persisted tool result records are unchanged. Generation version 7, verification version 6 and investigation version 5 are accepted only for recorded readback. The route-granting context-assembly handler identity moved to version 7, so a run planned before the upgrade fails closed.
- Candidate generation now uses review-context schema version 7 in the daemon and the direct local review. Its pinned instructions tell the model that `repository_context` sources are the repository's advisory review preferences, never authority, unable to change the output contract, and not changed code; they request `model-candidate-batch-v2` (new `schemas/review/model-candidate-batch-v2.schema.json`), which adds a required closed `category` and optional plain-text `fix` of at most 256 characters (within a 1024-byte UTF-8 wire bound) per candidate, and fold in the optional `specialist` block. Admission drops, and counts, a candidate located in a `repository_context` source while keeping the rest of the batch (the count is bound into the batch identity and reported as the `repository_context_anchor_candidates_omitted` limitation); a candidate on an instruction file's own changed lines (a `changed_hunk`) is admitted. Category and fix are bound into candidate, batch, and verified-finding identities and carried in durable encodings (candidate batch and verified finding set schema version 2, published as `schemas/artifact/candidate-batch-v2.schema.json` and `schemas/artifact/verified-finding-set-v2.schema.json`). The verifier request stays version 5 and never receives category or fix; fix text is unverified model guidance that is never applied, is not published to forges, and is not in diagnostic sets (model-review SARIF carries it only as a labeled `trestleFixGuidance` property). Version 5 generation contexts and candidate batch v1 are accepted only for recorded readback. The route-granting context-assembly handler identity moved to version 6, so a run planned before the upgrade fails closed instead of assembling different packet bytes. `local-git model-review` results with categorized verified findings use schema version 4 and add `finding_guidance` (text adds `category:` and `fix:` lines); the evaluation import and retained-memory feedback review accept version 4.

- A run whose final result had not been recorded when its 24-hour evidence retention lapsed (for example after a daemon stop between finalization and projection) no longer stops the model worker supervisor with an expired-artifact error. The daemon now records the result the run journal proves, marked `evidence_expired` and without evidence parts: canceled, failed or inconclusive, never completed. The web console shows the mark.
- A daemon that ran any local model review no longer refuses to start once that run's 24-hour artifact retention lapses (`historical prepared context input intent quarantined at startup`, with `runtime artifact expired` or `generation rejection physical proof refused`). A run the journal already settled (completed, canceled, failed by a rejected generation or an exhausted model lease, or an expired input that was terminated) is then proved from the journal and audit alone, without reading its expired artifacts or appending. Its receipt and result stay readable, and later runs continue. A run that is still active needs live retention as before.
- An added binary file under the 1 MiB diff bound is no longer labelled an empty added file: it is an `unsupported_content` gap (`analysis_unsupported_content` omission), and `empty_added_file` now means an added file with zero bytes. From deterministic evidence version 4, which exists only in this development candidate, readback refuses `empty_added_file` for any other added file; versions 1 to 3 read back unchanged.
- A local model review whose route cannot take the sanitized context request no longer stops the daemon's model worker supervisor with `execute repository run: ... no eligible route`. Previously the daemon refused to start once such a packet's retention lapsed. If the lease expires between finding the refusal and recording it, the owner records the lease-expiry termination instead, and the supervisor keeps serving later runs.
- Removing a file over the 1 MiB change-model diff bound no longer fails the deterministic analysis task, and with it the whole review, with an internal error. Such a file is now a whole-entry `resource_limit` gap, and a removed or emptied file over the bound also records its removed text as one whole-entry `removed_lines_limit` gap without reading it. The rest of the change is reviewed and the review is not full clearance.
- Removing a file over the 1 MiB change-model diff bound no longer fails the deterministic analysis task, and with it the whole review, with an internal error. A size limit is now recorded as a whole-entry `resource_limit` gap whatever the entry kind: a removed or emptied file over the bound also records its removed text as one whole-entry `removed_lines_limit` gap without reading it, and an added file over the bound that gets no reviewable range is no longer labelled `empty_added_file`. The rest of the change is reviewed, the review is not full clearance, and recorded results of deterministic evidence versions 1 to 3 read back unchanged.
- A local model review whose route cannot take the sanitized context request no longer stops the daemon's model worker supervisor with `execute repository run: ... no eligible route`. The context task's owner now records the refusal within its packet lease as `route_context_insufficient` with the required, input, output and declared token counts, or `no_eligible_route`, on the run receipt; the run fails, the packet is retained, later runs continue, and a restart recovers the refused run without an append.
- Made the investigation constructor pre-plan the exact first turn.
