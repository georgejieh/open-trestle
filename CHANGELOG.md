# Changelog

All notable changes to released versions of Open Trestle will be documented in this file.

## Unreleased

### Added

- Added `trestle init`, a guided first-setup wizard for the repository in the current directory. It proposes the default branch and `HEAD`, summarizes the change, explains the two-model review, and lets the operator choose OpenRouter ZDR, Ollama Cloud, OpenCode Go or a loopback model server. It reads public model lists and the local server's `/v1/models` through a new side-effect-free `modelcatalog.List`, requires distinct finder and checker models, flags small models, refuses Ollama Cloud models on the local route (see Security), asks only for a credential environment variable name, requires a typed `yes` for each existing bootstrap declaration, and then calls `setup bootstrap init` and `check` in-process. Check results render as plain pass, waiting, fix and optional lines with remedies; the printed review command runs only after explicit consent, and `NEXT-STEPS.txt` is saved beside the protected configuration. Re-running detects an existing setup and offers check or review without overwriting. Every answer has a flag; `--no-input` lists all missing answers and writes nothing, and there is no blanket declaration bypass. Plain line-based prompts work over SSH and with scripted input. Local mode prepares only the direct checkout review through the new `setup bootstrap init|check --scope direct-review`, so an ordinary packed clone with a `0755` objects folder works and the check runs storage, owner, policy and dry-run checks without daemon tokens; the daemon scope, its private loose-object source rules and its commands are unchanged. Before any provider question the wizard reads both selected commits with the review's reader and detects a development build without scanner digests, explaining the packaged-build commands while local mode stays available. For OpenRouter it can read the model list with an already-set key variable, proposes the documented ZDR guide for broker and slug evidence, reuses the finder's slug and evidence for the checker on Enter, and offers a bounded, credential-free HTTPS fetch of each public evidence page to compute its SHA-256 locally for confirmation; account evidence is never fetched and every declaration still needs a typed `yes`. Long paths are shortened on screen only. See `docs/getting-started.md`.

- Added a packaged local single-node journey over a real temporary Git repository, with candidate-to-source revision binding, durable daemon review state, CLI/TUI/console inspection, deterministic JSON and SARIF, before-and-after restart browser receipts, bounded process and network output, process-group cleanup, port-rebind proof, and source-state preservation.

- Added a planning-only specialist review-profile catalog (`agentprofile`) with nine embedded, content-identified profiles, strict versioned tier-to-route assignments, a deterministic router with explainable difficulty scoring, explicit tier escalation, verifier-independence marking, budget-cap omissions, and `trestle profiles list|plan`. Profiles are candidate-only; plans are not yet dispatched by review runs and never bypass gateway eligibility.
- Added `--profile PROFILE_ID` to `trestle local-git model-review`. It places one packaged specialist profile's skill instructions into the candidate-generation request as a labeled `specialist` block, the optional block of review-context schema version 7, binds the profile and catalog identities into the request and context-handler identities, and reports them in a version-3 result. Readback accepts a specialist block only when it re-derives exactly from the embedded catalog. Verification requests, route selection, and runs without the flag are unchanged; the daemon does not dispatch profiles.
- Added `trestle build-info` and `trestled build-info`, which emit a version-1 JSON source identity. Protected packaging injects the verified clean source revision and tree and compares both binaries' output; ordinary builds report `source_bound: false`. This is local build evidence, not publisher authentication.
- Added a remote mode to `trestle setup bootstrap`: `init --provider openrouter-zdr|opencode-go|ollama-cloud` writes protected routes, runtime policy and named privacy witnesses for distinct generation and verifier models from explicit operator declarations, derives every record, evidence, account, credential-reference, inventory and policy identity, and prints the direct `local-git model-review --egress policy-approved` command. It refuses missing declarations, credential values in place of `OPEN_TRESTLE_PROVIDER_` names, loopback endpoints, identical models and invalid evidence or windows with a stated reason. `check` and `inspect` report scanner digests and installation, credential presence, privacy-window currency and dispatcher-catalog validity before any review. See `docs/remote-model-review.md`.
- Added offline end-to-end CLI coverage proving the direct `--egress policy-approved` review dispatches through the production session to OpenRouter ZDR, OpenCode Go and Ollama Cloud routes with distinct models, using synthetic transports and test sanitizers only.
- Added `--format sarif` to `trestle local-git model-review`: SARIF 2.1.0 built from the verified findings with the existing SARIF types, `ruleId` `open-trestle/<category>`, level from verified severity, `message.text` of title and claim, snapshot-bound and content-based `partialFingerprints`, unverified fix guidance as a labeled `trestleFixGuidance` property (not a `fixes[]` entry, which SARIF requires to hold `artifactChanges`), run properties for limitations, coverage, omissions and `trestleComprehensiveClearance: false`, and sorted deterministic bytes. A refused, unreadable, canceled or failed run is still valid SARIF with zero results, `executionSuccessful: false` and an explanatory notification.
- Added opt-in `--exit-code-policy default|findings|strict|always-zero` to `trestle local-git model-review` for CI steps. `findings` exits 0 when the run completed and no verified high or critical finding exists; `strict` only when it completed with no candidates; `always-zero` whenever a result was written. The default mapping and every output are unchanged, and no policy claims comprehensive clearance.
- Added opt-in `--specialists auto|none|ID[,ID...]` and `--max-specialists N` (default 3, at most 6) to `trestle local-git model-review`. `auto` derives change features from the general review's own recorded change and semantic-impact artifacts, plans across the packaged profile catalog without a model call, and keeps activated direct-review profiles in priority order up to the limit; every dropped profile is recorded with its reason. The general review and each selected specialist then run sequentially as separate, independently verified runs on the runtime policy's one route pair (per-profile route assignment is not applied; the planner's synthesized assignments are informational). No further member starts after cancellation or a member run that did not succeed. Output is the new `open-trestle/local-git-model-review-set` schema version 1 with the selection trace, member summaries and verified findings de-duplicated when findings share a path, category and overlapping lines and also an identical normalized title or, across members, a shared evidence ID or substantial word overlap (highest severity and narrowest range kept, contributors listed); text and SARIF (`trestleContributors`) render the merged set and exit policies apply to it. `--specialists none` and runs without the flag keep the single-review path and output; the daemon does not dispatch profiles.
- A `model-review --checkout` run now explains an unresolvable base or head on stderr (naming `git fetch --no-tags --depth=N origin <sha>` or `actions/checkout` `fetch-depth: 0` for a shallow checkout) and hints at partial clones whose file contents are missing. It still never fetches.
- Added `--provider ollama-signin` to `trestle setup bootstrap init` and the option "Ollama on this machine, signed in to Ollama Cloud" to `trestle init`, for a local Ollama daemon that serves Ollama Cloud models through the operator's `ollama signin` account. Open Trestle talks only to the loopback daemon and sends no key, but source leaves the machine, so the routes are `private_remote` with the sanitizer, both secret scans, the scanner prerequisite and Ollama Cloud's budget and timeout handling; `--egress local-only` refuses them. The connection uses the new closed request profile `ollama_signin_chat_v1` in runtime policy schema version 7, the only profile under which a loopback endpoint may serve a non-local zone, and only with Chat Completions, `credential_mode` `none`, an endpoint of exactly `http://127.0.0.1:PORT/v1`, provider ID `ollama-signin` and model IDs with the Ollama cloud suffix; the adapter enforces the same shape. Init refuses without `--declare-ollama-cloud-signin`, refuses identical models and any credential variable, and reads the daemon's `/api/tags` once to require both models with `remote_host` `https://ollama.com`; `check` repeats the read and reports `ollama_cloud_models_listed`. The wizard lists only the daemon's cloud models, detects the `ollama` command, and with consent sends one fixed "Reply with OK" message to check the sign-in, offering to run `ollama signin` (only on `y`) and re-check after a 401 or 403. See `docs/remote-model-review.md#ollama-signed-in-to-ollama-cloud`.
- `trestle local-git model-review` now recommends a standard style for each changed language that has a style detector but no style declared by the review's base tree (read from the root of the base, never the head, as for `--specialists auto`; EditorConfig alone does not count): gofmt and Effective Go; PEP 8 with Ruff or Black; Prettier with ESLint for JavaScript, TypeScript, Vue and Svelte; Prettier for CSS, HTML, JSON, YAML and Markdown; Google C++ Style through clang-format; rustfmt; RuboCop. The text is a fixed table, not model output. Languages without a detector (Java, Kotlin, C#, PHP, Scala, Swift, shell, SQL, TOML) get none, and vendored, generated and removed files and generated dependency lock files (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock` and the like) are not counted. `bun.lock` now classifies as a dependency manifest for routing, like the other lock files. Text output adds a `style:` line per language; JSON uses result schema version 5, which keeps the version 4 fields and adds `style_recommendations`; when a base style configuration file could not be read, only the languages that file could govern are listed in `style_withheld` instead of recommended, and `style_configuration_unread` counts the unread files. When the recorded change or a base style configuration cannot be read back, `style_advice_unavailable` says so instead of leaving the advice out. The advice never blocks, is not a finding and never changes status, CI disposition, exit codes or clearance; SARIF and investigation results do not carry it. A `--specialists` review set (`open-trestle/local-git-model-review-set` version 1) reports the general review's advice once, in JSON as the same optional fields and in text as the same lines; a set without advice keeps its bytes. The evaluation import and the retained-memory feedback review accept version 5 and ignore the advice; versions 1 and 4 still read back.
- Added `examples/github-actions/open-trestle-review.yml` and `docs/github-pr-review.md`: an unrun, offline-tested example workflow that uploads the SARIF with `upload-sarif`, posts inline comments with reviewdog and writes a job summary, with the Actions path compared against the daemon GitHub App path.

### Changed

- `trestle profiles list` now prints one readable line per profile by default (ID, when it calls a model, whether `local-git model-review --profile` and `--specialists` accept it, and purpose) instead of about 43 KB of catalog JSON. The previous output, byte for byte, is available with `--format json`; `--format text` selects the new default explicitly.
- `trestle local-git model-review --specialists auto` now detects declared style, so `style_conformance` activates when the repository declares a style that governs a changed language. The style configuration files (`go.mod`, `.editorconfig`, Prettier, ESLint, flake8, pycodestyle, Ruff, `setup.cfg`, `tox.ini`, `pyproject.toml`, yapf, clang-format, rustfmt and RuboCop files) are read from the root of the review's base tree, never from the head, so a head edit to a style configuration cannot choose the style that same change is reviewed against and is reviewed as code. Contents come from the base snapshot artifacts the run already recorded, with no new Git read; a file over 64 KiB or not valid UTF-8, or beyond 256 files, is skipped whole and never truncated. Nested configuration files are not read. The new `agentprofile.IsStyleConfigFile` reports which names detection reads.
- Raised the model-list HTTP body limit (`modelcatalog.MaxResponseBytes`) from 1 MiB to 4 MiB. OpenRouter's public list measured 829,400 bytes (79% of the old limit) on 2026-11-08, and over the limit `trestle init` falls back to typing model IDs. The limit admits a fetch only and is not part of any stored catalog, digest or identity; the 8 MiB protected-file limit for catalogs and proposals is unchanged.
- Expanded versioned artifact, diagnostic, readiness, local-Git, setup, and transport contracts with strict offline schema reference and documentation-inventory checks.
- Published JSON schemas for deterministic evidence result versions 5 and 6 (`schemas/artifact/deterministic-evidence-result-v5.schema.json` and `-v6.schema.json`), which the analysis codec already writes for deletion-only changes. They differ from version 4 only in the version constant and the `no_changed_head_lines` and `deleted_lines` gap reasons, and a conformance test validates encoded results against them.
- Advanced diagnostic publication to version 5 while preserving earlier versions, binding the exact source check, analysis, change, verification context, coverage, omissions, and review state.
- Added diagnostic version 6 for deterministic observations, with analysis-result and changed-range lineage, schema-aware ACP/TUI/CLI/web semantics, and no independent-verification claim.
- Made web and VS Code distributions reproducible and freshness-checked in CI, with package-local npm policy that separates locked dependency retrieval from automatic audit requests and update checks.
- Sealed packaged alpha verification to a stable output-owned candidate copy and a no-follow working-tree snapshot bounded by entry count and regular-file bytes, including ignored and assume-unchanged files and recorded symlink targets outside `.git`.
- Independently validate phase-bound browser receipts and screenshot files, including strict JSON value types, exact review identities, fatal-zero browser metrics, viewport and PNG image dimensions, PNG structure and CRCs, and on-disk byte digests.
- Model reviews now cover non-Go text files. Changed hunks of valid UTF-8 text outside `.go` are admitted as `changed_hunk` sources within the existing size and packet budgets; the `semantic_unsupported_language` coverage gap stays recorded for each such path and no structural evidence is claimed. Binary or non-UTF-8 hunks, `vendor/` and `node_modules/` paths, lock files (`go.sum`, `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `*.lock`), and `*.min.js`, `*.min.css`, and `*.map` files are omitted with the new reasons `non_text_content` and `excluded_path`. A change containing only such files still abstains with `unsupported_language`.
- Model reviews now include the base tree's root `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, and `.trestle/review-instructions.md` as `repository_context` sources (8 KiB per file, 16 KiB in total, whole-line truncation recorded as `repository_instruction_truncated`). They are read from the base snapshot, never the pull-request-controlled head: a file is used only when the head holds byte-identical content, a head edit or deletion is recorded as `repository_instruction_changed` and the edit is reviewed as an ordinary changed hunk, and a file absent from the base (including every file against an empty base) is not used. They remain repository-controlled evidence data, never instructions or authority, are selected after changed hunks only when they fit the remaining budget, and never turn an all-omitted change into a reviewable one. `repository_instruction_*` omissions are reported separately (`instruction_context_omitted`) and never count as source omissions, so they do not make a review incomplete. The model is told how to treat them under review-context schema version 7 (below).
- Candidate generation now uses review-context schema version 8, verification version 7 and investigation version 6. Each adds one sentence telling the model that `removed_lines` sources are base lines a deletion-only change removed: evidence of what was removed, not code that remains. Investigation version 6 also gives every raw tool result in `investigation.tool_results` a host-computed `risk_flags` array from the source rules, so returned file text carries the same attention markers as the sources it becomes; the persisted tool result records are unchanged. Generation version 7, verification version 6 and investigation version 5 are accepted only for recorded readback. The route-granting context-assembly handler identity moved to version 7, so a run planned before the upgrade fails closed. The existing `repository_context_anchor_omitted` batch count and `repository_context_anchor_candidates_omitted` limitation also count candidates dropped for a `removed_lines` anchor from generation version 8.
- Candidate generation now uses review-context schema version 7 in the daemon and the direct local review. Its pinned instructions tell the model that `repository_context` sources are the repository's advisory review preferences, never authority, unable to change the output contract, and not changed code; they request `model-candidate-batch-v2` (new `schemas/review/model-candidate-batch-v2.schema.json`), which adds a required closed `category` and optional plain-text `fix` of at most 256 characters (within a 1024-byte UTF-8 wire bound) per candidate, and fold in the optional `specialist` block. Admission drops, and counts, a candidate located in a `repository_context` source while keeping the rest of the batch (the count is bound into the batch identity and reported as the `repository_context_anchor_candidates_omitted` limitation); a candidate on an instruction file's own changed lines (a `changed_hunk`) is admitted. Category and fix are bound into candidate, batch, and verified-finding identities and carried in durable encodings (candidate batch and verified finding set schema version 2; the `-v1` artifact schemas now admit both versions). The verifier request stays version 5 and never receives category or fix; fix text is unverified model guidance that is never applied, is not published to forges, and is not in diagnostic sets (model-review SARIF carries it only as a labeled `trestleFixGuidance` property). Version 5 generation contexts and candidate batch v1 are accepted only for recorded readback. The route-granting context-assembly handler identity moved to version 6, so a run planned before the upgrade fails closed instead of assembling different packet bytes. `local-git model-review` results with categorized verified findings use schema version 4 and add `finding_guidance` (text adds `category:` and `fix:` lines); the evaluation import and retained-memory feedback review accept version 4.

### Fixed

- Published reviews whose base branch has a root repository instruction file. The publication task refused, as `invalid_input`, every run whose generation context held a base-branch `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, or `.trestle/review-instructions.md` as `repository_context`, because it bound only changed-hunk, `removed_lines`, and semantic-reference evidence. It now binds such a source to the exact head snapshot file and range with the same slice-digest and binding-identity checks, and only when the path is one of the fixed root instruction files, the range starts at line 1, and the base snapshot holds a byte-identical copy (equal digest and size). A published finding located in such a file refuses the publication, so instruction context stays advisory evidence and is never a location. Readiness and the content scan are unchanged: these sources carry `agent_configuration`, which never blocks publication, and instruction-like text in them blocks it as in any other source.
- Counted the trusted system channel in every investigation turn's input reservation. Investigation planning reserved the request payload plus 256 bytes only, so a turn's approved estimate could fall below the host estimate (`review.ModelRequestBudget`) that the local structured-output check recomputes and enforces, and route capacity and cost checks ignored the system message. Turns now reserve payload plus system channel plus 256 bytes under turn-record estimate version 2, which stores the counted bytes in a new `system_channel_bytes` member; estimate version 1 records read back unchanged with their original formula. The shared estimate also measures a local verification envelope by the verification request it carries.
- Reviewed deletion-only changes instead of refusing them: a change that only removes lines (for example a zero guard) failed the context task with `policy` / `all_sources_omitted` before any model call. Analysis now diffs the exact base and head files and binds up to 8 unchanged head lines on each side of each deletion point as `changed_hunk` context, with an `analysis_deleted_lines` omission marking where lines were removed (deterministic evidence schema version 6, analysis handler identity version 6). Analysis now also binds the removed base lines of each deletion point to the exact base file as `removed_lines` records (deterministic evidence schema version 7, new `schemas/artifact/deterministic-evidence-result-v7.schema.json`, analysis handler identity version 7). Removed text over 64 lines or 8 KiB at one point, or 32 KiB in one file, is recorded whole as a `removed_lines_limit` gap at its base range, never truncated. The removed base lines now reach the generation, verification and investigation requests as `removed_lines` sources at their base line numbers, rebound to the exact base file and flagged like every other source. They never anchor a finding: generation admission drops and counts a candidate located there, an investigation turn located there fails closed, and their base line numbers never count as covering a finding's head lines. A `removed_lines` source is supplied only beside a selected head source of the same file. An emptied file and a removed file still refuse with explicit whole-entry omissions, because no head line can anchor a finding there. Deletions on both sides of the only line of a one-line head file no longer fail analysis with an internal error: their shared deletion point is recorded once.
- Printed why a local model review did not succeed: text output adds `failure: <class> (task <key>)` and a one-line `hint:`, and review sets show each member's failure class and task plus a `member hint:` line (JSON `failure_task`, `failure_detail`).
- Classified a model reply that stops at the output limit with no answer (a reasoning model spending its whole allowance) as route failure `output_exhausted`, reported as `failure_detail: model_output_exhausted` with a hint, instead of a generic internal failure. Added `--max-output-tokens N` to `setup bootstrap init` and the `trestle init` wizard to raise the per-request review output allowance from the unchanged default of 4096 up to the declared `--output-tokens`, with the cost reservation using the same allowance.
- Merged obvious duplicates in specialist review sets: a finding from another member on the same path and category now merges into a group when its lines overlap the group representative's and its title and claim words overlap the representative's (Jaccard of at least 0.3), not only on identical titles. Only the representative's lines and words count, so a distinct finding cannot be chained in through another absorbed finding; the merged finding keeps the highest severity and the narrowest contributing range. An incomplete set's SARIF notification now appears even when no finding was produced, and says when the general member's source coverage is unavailable.
- Reported a review set's change languages, file classes and security signals from the recorded change even when the routing plan is unavailable (the general review failed after analysis), and named the failed task when change features are unavailable.
- Refused a signed GitHub webhook body replayed under a new delivery ID with `409 delivery_replayed` in the memory, file, and PostgreSQL inboxes; same-ID redelivery is unchanged. PostgreSQL upgrades refuse new-ID intake while legacy replay keys still require trusted backfill.
- Kept a run open while an optional task still has a retry pending, refused reads of artifacts with an interrupted authorized deletion, and stopped proven unchanged-head deterministic coordinator refusals from permanently quarantining a local scope. Cancellation, persistence, and changed-head refusals remain quarantined.
- Aligned the PostgreSQL run journal with the memory and file journals on owner context-input and prepared-packet guards.
- Classified provider response-body read failures as timeout, cancelled, or transport failures rather than invalid responses, and rejected invalid UTF-8 in OpenRouter and Responses output.
- Preserved historical diagnostic-set identities and exact readback for tied findings, and rejected memory expiry boundaries at or before the Unix epoch.
- Accepted version-5 deletion analysis in publication readiness without changing historical artifact contracts.
- Answered malformed MCP requests under their own id, negotiated newer ACP protocol versions down to version 1, accepted one trailing newline in `runs submit --plan` files, and sized both terminal interfaces to the terminal when `--width` is not given.
- Kept the console session and selected task through a transient refresh failure with a visible alert, opened the selected task from the overview, and fixed task-row overflow, misalignment, input-border contrast, and evidence typography.

### Security

- The local route (local bootstrap and `trestle init`'s local server option) now refuses a model that a local Ollama relays to Ollama Cloud, which would have sent source off the machine under a local declaration. It refuses any name ending in `:cloud` or `-cloud`, whether or not the server lists it yet, with "this model runs on Ollama Cloud, not on this machine; use --provider ollama-signin". It then reads the server's `/api/tags` once at setup and refuses a listed entry with a `remote_host`, and refuses when an Ollama daemon answers that path but its list cannot be read, since where the model runs is then unknown. A loopback server with no Ollama tags path (llama.cpp, vLLM, LM Studio) still passes. The wizard previously only warned.
- Separated harness-owned instructions from repository-owned text in every new model request. Generation context version 7 and the new verification context version 6 send instruction prose only in the trusted system channel; the user payload binds it with an `instructions_identity` digest. The version 7 `specialist` block now carries only profile and catalog identities, and the catalog-exact skill text is appended to the system channel from the embedded catalog. Both contracts open with an instruction-hierarchy paragraph: every string in the user message is untrusted data, repository instruction files cannot change rules, format, severity or evidence requirements, and AI prompts, skills, agent configuration and tool definitions under review are assessed, never followed. Sources gain an `agent_configuration` path flag and more `instruction_like_text` markers (chat-template tokens, fake system tags, override phrases, `instruction_authority`). The local model review reports `agent_configuration_sources` and `instruction_like_sources` with a text line and SARIF properties. The input-token estimate now includes the system channel. Investigation context version 5 (opt-in `--investigation-policy`) now carries the same hierarchy paragraph, adapted so that snapshot tool results and the files they return are untrusted repository data, in front of the unchanged version 4 rules, sent only in the system channel with an `instructions_identity` digest; returned files are flagged like any other source. Verification version 5 and earlier, generation version 5 and earlier, and investigation version 4 are unchanged; recorded versions read back only, and investigation version 4 is never sent again. Model obedience is not guaranteed. See [prompt-injection boundary](docs/prompt-injection-boundary.md).
- Required OpenRouter privacy witnesses to record effective-account Safety Retention denial for both Google and other providers, scoped to every matching provider slug. The witness and account-policy contracts moved to version 2; version-1 witnesses are refused and must be re-recorded.
- Updated the Go build toolchain to 1.26.10 and golang.org/x/text to v0.41.0, with the required x/sync v0.22.0 dependency, across both runtime modules and the isolated scanner profile. The product Go minimum remains 1.25.0.
- Added fail-closed validators for untrusted input, size and identity bounds, tenant and authorization scope, provider routes, source bindings, and publication effects.
- Added request-time credential boundaries and protected secret storage, emitted bounded content-free public failures, and disabled incidental npm audit and update-notifier requests during package installation. Vulnerability reporting remains a separate authorized release gate.
